## Context

现有权限模型只有一层：`用户 → 角色 → 权限码集合`，接口与菜单各自声明"我要哪个码"，
命中即放行。这套模型的优点要保留（简单、fail-closed、菜单与接口同源），
缺的是**码本身的结构**。

四条硬约束来自终局架构，不是从现状推的：

| 约束 | 推论 |
|---|---|
| 多方开发，子应用声明权限但不能自己授权 | 码必须**可归属、可校验** |
| 同一份判定在四处跑 | 核心必须**零依赖、可跨进程** |
| 服务能力不能靠转发用户 token 获得 | 统一**形态**，不统一**授权来源** |
| L1 不认识任何 L2 | 平台**不能**理解业务域的数据模型 |

## Goals / Non-Goals

**Goals:**
- 一个可以在 optimus-api / partner-service / optimus-ui / 子应用 iframe 四处运行的
  纯函数判定核心
- 码的结构能表达归属（namespace）、对象（resource）、动作（action）
- 声明 DSL 产出**带类型的常量**，拼错在编译期就报——当前码是自由字符串，
  错一个字母的表现是"莫名其妙 403"，排查时很难想到是配置问题

**Non-Goals:**
- **本期不接线**：不改 `@Perm`、不改 `filterMenus`、不建任何表、不迁任何码
- 不实现数据范围（scope）判定——只在返回类型里留位
- 不做 NestJS / React 适配层（第三期随接线一起做，届时才知道真实的接入形状）
- 不解决四个已验证的菜单缺陷（顶层泄漏、PermissionModal、orderNum、config_center）
  ——那些在第三期

## Decisions

**只认三段式，不做兼容层**（2026-09-06 拍板）。项目尚未上线，没有存量用户依赖这批码。
兼容层的代价是双格式解析要一直维护，而"某天有人来清理"通常不会到来。
直接后果是核心少一条解析分支、少一类边界用例。

**`evaluate` 返回 `Decision` 对象而不是 boolean。** 数据范围是迟早要加的一维
（"渠道经理只看自己名下的合伙人"）。返回值一开始就是对象，后面加 scope 不用改
所有调用点——这是很便宜的前瞻。第一版 `scope` 恒为 `'all'`。

**scope 不编进码。** `partner:profile:read@own` 会让码组合爆炸，且 scope 的语义因业务
而异（"自己的"在合伙人业务是 `channelManagerId`，在订单业务是 `regionId`）。
码只回答"能不能做这类事"，范围是独立的一维，由平台存与传、子服务翻译成 where 条件。

**规则链留口子但只实现一条。** `options.rules` 默认 `[holdsCode]`。将来要加"且资源归属
于自己"、"且在时间窗内"，追加一条 rule 即可，不动核心。**刻意不预先实现**——
和 grant code "只定义确实已有消费方的项"同一个判断。

**零运行时依赖，框架适配留到第三期。** 主入口要能被三方独立安装，也要能在浏览器里跑。
适配层放到接线时做：现在写的适配形状大概率不是接线时实际需要的那个。

**通配只做后缀通配，不做中缀。** `partner:*` 与 `partner:campaign:*` 合法，
`*:campaign:read`（任意服务的活动读权限）**不支持**——它跨越了命名空间边界，
而命名空间边界正是这套设计的安全支点。允许中缀通配等于开了一个绕过归属校验的口子。

## Risks / Trade-offs

**[风险] 没有兼容层，第二期的重命名必须原子完成**——`@Perm` 声明、`SYSTEM_ROUTES`
的 `code`、`op_sys_role_menu` 的数据三处同时切换，漏一处就是 403。
→ 缓解：接口已 fail-closed，**迁错会立刻报错而非静默放行**，错误可见。
但仍需完整对照表 + 回滚脚本 + 逐角色实际登录验证。这是第二期的任务，不是本期。

**[风险] `definePermissions` 的类型推导可能过度设计**，为了漂亮的 `P.campaign.write`
写一堆条件类型，反而难维护。
→ 缓解：类型部分保持在"能推出字面量联合"的最小程度，推不动就退回 `as const` 手写。
可读性优先于类型体操。

**[取舍] 本期交付物无人消费。** 包写好了但不接线，短期看不到价值。
→ 这是有意的：接线要动 `@Perm` 与菜单过滤，是有风险的改动；先把纯函数部分做扎实、
测透，接线时才能确信"出问题不是核心的锅"。
